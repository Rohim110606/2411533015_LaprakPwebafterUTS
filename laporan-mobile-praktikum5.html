Aplikasi Mobile

Praktikum 5

PENDAHULUAN

Pengembangan aplikasi mobile yang kompleks memerlukan tata kelola arsitektur navigasi yang terstruktur dan terevaluasi dengan baik untuk menjaga keterbacaan serta pemeliharaan kode program clean code. Dalam kerangka kerja Flutter, perpindahan antarlayar yang dilakukan secara eksplisit tanpa pengorganisasian rute yang terpusat berpotensi menimbulkan kendala struktur program spaghetti code seiring bertambahnya fitur. Oleh karena ini, penerapan mekanisme Named Routes menjadi salah satu pendekatan standar untuk mengelola pemetaan rute aplikasi secara terpusat.

Selain pengelolaan rute utama, antarmuka pengguna User Interface pada aplikasi modern menuntut kemudahan aksesibilitas antarfitur utama secara efisien. Komponen Bottom Navigation Bar hadir sebagai solusi untuk mengintegrasikan beberapa tampilan halaman seperti Beranda/Dashboard, Riwayat, dan Profil dalam satu wadah tampilan utama tanpa harus merestrukturisasi Scaffold secara keseluruhan. Implementasi gabungan ini memungkinkan perpindahan layar berlangsung secara dinamis melalui pengelolaan status state management indeks tab yang aktif.

Adapun batasan pembahasan pada materi praktikum ini difokuskan pada penerapan Named Routes untuk navigasi terpusat serta pengintegrasian Bottom Navigation Bar menggunakan Stateful Widget pada aplikasi studi kasus pengelola keuangan berbasis Flutter. Pembahasan tidak mencakup manajemen state tingkat lanjut maupun integrasi basis data dan layanan backend.

TUJUAN

  • Mahasiswa mampu menerapkan struktur navigasi terpusat menggunakan Named Routes pada Flutter guna mencegah spaghetti code serta mempermudah pemanggilan rute halaman aplikasi
  • Membangun komponen navigasi bawah mampu mengelola dan menampilkan pergantian halaman utama secara dinamis
  • Mahasiswa mampu mengintegrasikan seluruh alur perpindahan antarlayar

ISI

1. Pertama-tama perlu kita buat kodingan yang berfungsi untuk menjalankan aplikasi utama Flutter bernama "Expense Tracker Final". Di dalamnya, terdapat pengaturan tema warna dasar aplikasi serta penentuan halaman login sebagai tampilan awal yang akan muncul ketika aplikasi dibuka.

2. Selanjutnya kita akan membuat kodingan yang berfungsi untuk mengelola navigasi menu bawah pada aplikasi yang memungkinkan pengguna berpindah halaman antara Beranda, Riwayat, serta Profil secara dinamis. Di dalamnya terdapat penyimpanan status halaman aktif dan pengiriman data email ke halaman profil pengguna.

3. Kemudian kita akan membuat kodingan yang berfungsi untuk membuat halaman login aplikasi yang dilengkapi dengan formulir validasi email, tombol aksi, serta pengiriman data teks email menuju halaman utama (MainScreen) setelah validasi berhasil.

4. Kemudian kita akan membuat kodingan yang berfungsi untuk menampilkan halaman profil pengguna yang berisi informasi nama, email, dan status akun, lengkap dengan tombol keluar atau logout yang akan memunculkan kotak dialog konfirmasi sebelum kembali ke halaman login.

5. Kemudian kita buat kodingan yang berfungsi untuk membangun struktur tampilan antarmuka halaman utama aplikasi keuangan dengan memanfaatkan komponen dasar seperti Scaffold untuk kerangka halaman, AppBar untuk judul di bagian atas, FloatingActionButton sebagai tombol aksi cepat untuk berpindah ke halaman tambah transaksi, serta SingleChildScrollView dan Column yang membungkus kartu informasi saldo dan daftar riwayat transaksi agar dapat digulir dan disusun secara vertikal.

6. Setelah itu, buat kodingan yang berfungsi untuk menyediakan antarmuka daftar riwayat keuangan secara efisien dengan memanfaatkan komponen ListView/List.generate untuk memproses kumpulan data transaksi secara otomatis lengkap dengan penyesuaian ikon, warna kategori, dan nominal uangnya, sekaligus menangani fungsi navigasi (routing) agar pengguna dapat beralih ke halaman detail saat salah satu item transaksi ditekan.

7. Selanjutnya kita akan membuat kodingan yang berfungsi untuk membangun kerangka antarmuka halaman detail berbasis StatelessWidget yang memanfaatkan parameter constructor wajib (required) untuk menangkap data kiriman secara dinamis, lalu menyusunnya secara rapi menggunakan komponen Column, ikon utama, teks berukuran besar untuk nominal, serta widget pembantu _buildDetailRow guna menampilkan rincian informasi transaksi secara terstruktur dan mudah dibaca.

8. Terakhir, kita perlu membuat kodingan yang berfungsi untuk mengelola proses input data keuangan secara dinamis dan aman, di mana controller dan form key bekerja sama untuk memvalidasi agar semua kolom wajib terisi dengan benar, widget showDatePicker memudahkan pemilihan tanggal berformat DD/MM/YYYY secara akurat, dan fungsi Navigator.pop memungkinkan aplikasi kembali ke halaman sebelumnya secara otomatis setelah transaksi berhasil disimpan.

KESIMPULAN

Berdasarkan modul praktikum yang telah dipelajari, dapat disimpulkan bahwa penerapan Named Routes dan Bottom Navigation Bar sangat efektif dalam meningkatkan efisiensi arsitektur navigasi serta kualitas antarmuka aplikasi Flutter. Penggunaan Named Routes mempermudah pengorganisasian pemetaan rute secara terpusat pada MaterialApp sehingga kode program menjadi lebih rapi dan mudah dipelihara, sementara Bottom Navigation Bar memberikan pengalaman pengguna (user experience) yang interaktif dan responsif dalam mengakses berbagai layar utama tanpa mengganggu struktur dasar aplikasi.
